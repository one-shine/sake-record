# テスト規約

<!-- frontmatter は必ず1行目から始める(上に HTML コメントを置くと paths スコープが効かない)。 -->

- 新機能・バグ修正には必ず失敗するテストを先に書いてから直す(TDD)。未実装機能のモック実装で通したことにしない。
- **回帰テストは、修正を外して赤くなることを確認して初めて回帰テストになる。** 書いたら使い捨てで fix を revert し、落ちることを見る。
- 単一テストを優先して回す。`npm test -- linkBrand` のようにパターンを付ける(素の `npm test` は許可設定でブロックされる)。
- ドメインロジックは外部依存なしで単体テストできる形に保つ。`src/domain/` のテストは jsdom を必要としない。
- **すべてのルール・分岐が実データで最低1回は発火することを保証する。** 恒真・恒偽の条件は静かに機能を殺す(例: エイリアス表の各エントリが実際に紐付け件数を増やしているか変異テストで確かめる)。
- 集計指標が緑でも個票が正しいとは限らない。ユーザーが実際に見る粒度(1行・1件)で検証する。
- エッジケース(空・境界・未紐付け等)を明示的に1ケースずつ。
- Node の型が必要なテストは当該ファイルで `/// <reference types="node" />` する。tsconfig の `types` に `node` を足さない(本番 `src` に `process`/`Buffer` が漏れる)。
- IndexedDB を触るテストは `fake-indexeddb` を使う。
